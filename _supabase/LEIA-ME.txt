DOAÇÕES PELO MERCADO PAGO — COMO FUNCIONA E ONDE FICAM AS CHAVES
==================================================================

Peças (todas no Supabase, projeto luyuprliobxtxnppdohw):
  - Função mp-doacao   → o botão "Doar com Mercado Pago" da aba Doar chama esta função. Ela cria a
                         preferência do Checkout Pro e devolve o link de pagamento do Mercado Pago.
  - Função mp-webhook  → o Mercado Pago avisa aqui quando um pagamento muda. Ela confere a assinatura,
                         busca o pagamento no Mercado Pago e, se aprovado, lança o apoio na Aliança Z.
  - Tabela mp_pagamentos e função registrar_apoio_mp (no banco) → guardam cada doação e somam no mural.
  Cópias do código: functions/mp-doacao, functions/mp-webhook e migrations/ (esta pasta).

SEGREDOS (Painel do Supabase → Edge Functions → Secrets → Add new secret)
  MP_ACCESS_TOKEN    Painel do Mercado Pago → app Zenkyo → Credenciais.
                     Para testar: aba "Teste". Para receber de verdade: aba "Produção".
  MP_WEBHOOK_SECRET  Painel do Mercado Pago → Suas integrações → app Zenkyo → Webhooks →
                     "Assinatura secreta" (aparece depois de cadastrar o endereço do webhook).
  SITE_URL           (opcional) endereço do site para a volta do pagamento.
                     Padrão: https://zenkyo.com.br/ (o site no ar)
  Nunca cole essas chaves no código do site (o repositório é público) nem em conversa nenhuma.

ENDEREÇO DO WEBHOOK (cadastrar no painel do Mercado Pago, evento "Pagamentos"):
  https://luyuprliobxtxnppdohw.supabase.co/functions/v1/mp-webhook

QUEM APARECE NO MURAL
  - Logado com Discord: soma no apoiador ligado ao perfil (patente sobe sozinha).
  - Sem login, com nome: entra uma linha nova no mural com esse nome.
  - Anônimo (ou sem nome e sem login): fica só registrado em mp_pagamentos, fora do mural.

SE ALGO DER ERRADO
  Painel do Supabase → Edge Functions → mp-doacao / mp-webhook → Logs.

DOAÇÕES INTERNACIONAIS PELO KO-FI (site em inglês, zenkyo.com.br/en/)
=======================================================================
  Em dólar, sem CNPJ: a pessoa doa na página do Ko-fi (cartão ou PayPal) e o Ko-fi repassa para a conta do dono.
  O Ko-fi não deixa o site criar o pagamento nem voltar para cá, então o apoio entra por um aviso (webhook).
  - Função kofi-webhook → o Ko-fi avisa aqui a cada doação (tipos Donation e Subscription). Confere o verification_token do
                          aviso com o segredo KOFI_VERIFICATION_TOKEN e chama registrar_apoio_kofi. Publicar SEM verificação de JWT.
  - Banco: migrations/20261030_kofi_doacoes.sql → provedor 'kofi' em mp_pagamentos e a função registrar_apoio_kofi, que acha o
           perfil pelo código e reaproveita registrar_apoio_mp (patente sobe sozinha). A coluna valor continua em REAIS
           (dólar x taxa fixa); valor_original guarda o dólar; mp_payment_id guarda o kofi_transaction_id (não lança duas vezes).
  - Site: KOFI_URL em js/app.js (hoje vazio: /en/ mostra "em breve"). Ponha o endereço da página, ex.: https://ko-fi.com/seunome
  COMO O APOIO CHEGA NO PERFIL
    Logado com Discord, o site mostra o código ZK-XXXXXXXX (os 8 primeiros caracteres do id do perfil). A pessoa cola o código na
    MENSAGEM da doação no Ko-fi; o webhook lê a mensagem, acha o perfil e soma no apoiador (patente automática).
    Sem código: entra no mural pelo nome digitado no Ko-fi, como apoiador novo (sem patente de perfil).
    Doação marcada como privada no Ko-fi: fica registrada, mas fora do mural.
  SEGREDOS (Painel do Supabase → Edge Functions → Secrets):
    KOFI_VERIFICATION_TOKEN   Ko-fi → Settings → API → Webhooks → "Verification Token".
    USD_BRL                   (opcional) taxa fixa; padrão 5. Precisa ser igual a KZ_USD_BRL em js/i18n.js.
  ENDEREÇO DO WEBHOOK (colar em Ko-fi → Settings → API → Webhooks → Webhook URL):
    https://luyuprliobxtxnppdohw.supabase.co/functions/v1/kofi-webhook
  LIMITES: só dólar (deixe a página do Ko-fi em USD; outras moedas são ignoradas e aparecem nos logs); o Ko-fi NÃO avisa
  reembolso (ajuste à mão na aba Admin); doações de loja e comissões não entram. Mínimo US$ 1 (= R$ 5 pela taxa fixa).
  Teste: o botão de teste do painel do Ko-fi (se houver) pode lançar uma doação de exemplo no mural; confira e remova na aba Admin.
  O teste de verdade é doar US$ 1 com o código do perfil.
  Logs: Painel do Supabase → Edge Functions → kofi-webhook → Logs.
IA DO MONTADOR DE TIME (Descreva o time; Gemini, plano gratuito)
================================================================
  - Função ia-montador → duas ações: "interpretar" (pedido → filtros e guerreiro principal) e "explicar" (explica os times que o
                         SITE montou, só com os dados que o site mandou). A IA nunca escolhe guerreiros. Publicar SEM verificação de JWT.
  - Banco: migrations/20261028_ia_montador.sql (tabelas ia_uso e ia_avisos + funções ia_consumir, ia_devolver, ia_avisar, ia_tem_aviso).
  - Aberta a qualquer visitante (sem login). Limites por dia: IA_LIMITE_VISITANTE (padrão 12 chamadas) e IA_LIMITE_GLOBAL (padrão 200).
    Cada pedido do site usa 2 chamadas (interpretar + explicar). O visitante é contado por um hash do IP, nunca pelo IP.
  - NUNCA GASTA DINHEIRO: use uma chave do Google AI Studio de um projeto SEM cobrança (não ative billing). Se o plano gratuito acabar
    (erro 429 "por dia"), a função para de chamar a IA no resto do dia, o site usa a leitura simples e o dono é avisado UMA vez por dia.
  SEGREDOS (Painel do Supabase → Edge Functions → Secrets):
    GEMINI_API_KEY         Google AI Studio → Get API key (projeto sem billing).
    AVISO_DISCORD_WEBHOOK  (recomendado) endereço de webhook de um canal privado do Discord: Configurações do canal → Integrações → Webhooks.
                           É por ele que você é avisado quando o limite gratuito acaba. Sem ele o aviso só aparece nos logs da função.
    IA_MODELO              (opcional) padrão gemini-2.5-flash; confira os modelos com plano gratuito em ai.google.dev/gemini-api/docs/pricing.
    IA_LIMITE_VISITANTE / IA_LIMITE_GLOBAL / IA_SAL   (opcionais) ver acima.
  Ver o uso: Google AI Studio → Dashboard/Usage. Ver quando o limite acabou: tabela ia_avisos (motivo limite_gemini_diario).
  A função antiga ia-time (Anthropic) não é mais usada e pode ser apagada.

--- Funções do Supabase (pasta supabase/functions) ---
mp-doacao (cria a preferência), mp-webhook (aviso do Mercado Pago), mp-retorno (confirma na volta ao site),
mp-conferir (conferir um pagamento, só o dono), mp-reconciliar (confere os pedidos abertos, só o dono; roda na aba Admin).
Funções antigas que podem ser apagadas no painel (Edge Functions): mp-pix, ia-time (não são mais usadas).

--- Esta pasta (_supabase) ---
É a CÓPIA DE SEGURANÇA do backend do Zenkyo: funções (functions/), migração dos pagamentos (migrations/) e o retrato do banco
(schema-snapshot.sql: tabelas, funções, vistas, políticas, gatilhos e tarefas). Não contém segredos nem dados de pessoas.
O GitHub Pages não publica pastas que começam com "_", então ela fica no repositório mas fora do site.
Depois de mudar uma função ou o banco no Supabase, atualize aqui também (e rode node build.js se mudar o site).
